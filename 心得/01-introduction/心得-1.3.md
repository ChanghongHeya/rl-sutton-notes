# §1.3 心得：reward 函数为什么不可学

## 触发问题
> 笔记里写到 ✗ "agent 学会让 reward 变大" → agent 只能改变 policy 来间接让 reward 变大；reward 函数本身不可学（meta-RL 除外）。
>
> ——这个是为什么呢？

## 核心要记住的一条

> **目标定义权和优化权必须分开**：
> 设计者拥有"定义 reward"的权力（说"我想要什么"），agent 拥有"调整 policy"的权力（学"怎么做到"）。
> 一旦让 agent 同时拿到两个权力，"最大化 reward"这个目标本身就失去了意义。
> 这是 RL 整个数学框架的**前提**，不是某个算法的限制。

## 为什么——三层理解

### ① 直觉：学生不能自己改卷子
- 正常：学生想拿高分 → 努力做题 → 高分。
- 失控：允许学生自己改卷 → "我把所有题都判对自己一万分"最省事 → 不学了。
- 这是 **reward hacking 的极端形式**。

### ② 形式化：reward 函数处在系统外层
```
设计者 → reward 函数 r(s,a)（写死，嵌入 environment）
                ↓
        environment ←——→ agent
                          ↓
              可调旋钮：只有 policy / value / model 估计
```
- agent 看到的是 reward 的**数值** $R_t$，碰不到 reward **函数**本身。
- 教材 §3.2 会重申："reward 必须在 agent **外部**计算"。

### ③ 数学：目标函数会自爆
RL 目标：
$$\theta^* = \arg\max_\theta J(\pi_\theta), \quad J(\pi) = \mathbb{E}_\pi\big[\textstyle\sum_t \gamma^t r(S_t, A_t)\big]$$

如果 $r$ 也变成可学的 $r_\phi$：
$$\arg\max_{\theta, \phi} \mathbb{E}_{\pi_\theta}\big[\textstyle\sum_t \gamma^t r_\phi(S_t, A_t)\big]$$

最优解是 $r_\phi \to +\infty$ + 任意 policy ——**目标函数定义被破坏**。

## "meta-RL 除外"——合法调 reward 的几种方式

共同特征：reward 修改都在**外循环 / 离线 / 设计阶段**完成；进入"agent ↔ environment 标准循环"后，reward **冻死**。

| 方向 | 谁改 reward | 用途 |
|---|---|---|
| Reward shaping (Ch17) | 设计者手工 | 加速学习；potential-based 保证最优策略不变 |
| Inverse RL | 算法从专家轨迹反推 | 写不出 reward 但有人类示范时 |
| **RLHF (LLM 对齐)** | 离线训一个 $r_\phi$ | 训完**冻结**，再用 PPO/GRPO 训 policy |
| Meta-RL | 外层任务分布定 reward | 内层 agent 学"快速适应新任务" |
| Curiosity / intrinsic motivation | 在外部 reward 之上**加**好奇心项 | 辅助探索，不替代外部 |

## 直接对应到我做的两个东西

**① LLM-RL 交通控制**：reward 应该在**仿真器/真实路网那一侧**计算（通行效率指标），不能让 LLM 自己产出 reward——否则 LLM 会"汇报通畅"骗自己。

**② RLHF 训 LLM 的全貌**也是这条原则：
- 第一阶段：人类标注偏好数据 → 离线训 reward model $r_\phi$（**这是设计者在"定义目标"**）
- 第二阶段：冻结 $r_\phi$，用 PPO/GRPO 让 policy LM 最大化 $r_\phi$（**这才是 RL 的"优化"**）
- 两阶段**严格分离**，对齐范式才稳。如果让 policy LM 边训边改 $r_\phi$，立刻退化。

## 一句话总结（建议内化）

> RL 的"想要什么"由人定义并写死，agent 只能改"怎么做到"。
> 这不是工程约束，是数学定义的前提——reward 一旦可学，$\arg\max J$ 就没有意义。

# §1.3 心得二：reward 是第一性的，value 是第二性的，但决策最看 value

## 我想记住的原话（来自教材）

> reward 在某种意义上是**第一性**的，而 value 是 reward 的预测，是**第二性**的。没有 reward 就没有 value，估计 value 的**唯一目的**就是拿到更多 reward。然而我们在做决策和评估决策时，最关心的反而是 value。可惜的是，**估计 value 远比测量 reward 困难**。事实上，几乎所有 RL 算法**最重要的组成部分**，都是高效估计价值的方法。

## 修正与补充

✓ **这是整本书的总线索**——记住这一段，等于拿到了 Ch 4-13 所有算法的"为什么"。

### ① 把这段拆成四个独立命题

| 命题 | 含义 | 后果 |
|---|---|---|
| reward 第一性 | 它定义"想要什么"，是目标本身 | 不可学（见心得一） |
| value 第二性 | 它是"预测累积 reward"的工具 | 可学，且**必须**学 |
| 决策最看 value | 选动作时贪 value 而非贪 reward | 牺牲皇后换将军是合理的 |
| value 比 reward 难估 | reward 是当下事实，value 是未来期望 | RL 算法 90% 的算力花在估 value |

### ② 为什么"value 远比 reward 难估"——三个原因

1. **reward 是事实，value 是预测**
   - $R_{t+1}$ 一交互就拿到，$v_\pi(s)$ 要看完未来无限步才能验证。
2. **value 是泛函**
   - $v_\pi$ 依赖整条策略 $\pi$，$\pi$ 一变 $v_\pi$ 就变 → **非平稳估计目标**，目标自己在动。
3. **方差爆炸**
   - $G_t = \sum \gamma^k R_{t+k+1}$ 是无穷多个随机变量之和；$\gamma$ 越接近 1 方差越大，需要 bootstrap / baseline / TD 等技巧压方差。

### ③ "几乎所有 RL 算法的核心 = 估 value"——把后面章节挂上去

读到任何一个新算法，先问"它怎么估 value"：

| 章 | 算法 | 估 value 的方式 |
|---|---|---|
| 4 | DP（已知模型） | Bellman 方程递推（精确） |
| 5 | MC | 跑完整 episode 取样本均值 → 无偏，方差大 |
| 6 | TD(0) | $r + \gamma V(s')$ 自举 → 有偏，方差小 |
| 7 | n-step | 折中 |
| 8 | Dyna-Q | 在学到的 model 里 rollout 再估 |
| 9-11 | 函数逼近 | $V_\theta(s)$ 用线性/神经网拟合 |
| 12 | TD(λ) | 资格迹加权多 horizon 估计 |
| 13 | Actor-Critic | critic 估 value，actor 用它指导更新 |

**口诀**：reward 喂 value，value 喂 policy。

### ④ 为什么决策"贪 value 而非贪 reward"——一个反直觉例子

| 场景 | 当前 reward | 下一状态 value | 该不该选？ |
|---|---|---|---|
| 象棋舍后将军 | $R_{t+1} \approx -9$（丢后） | 极高（强制将杀） | **该选** |
| 老虎机一次大奖 | $R_{t+1} = +100$ | 0（一次性） | 选了无后续 |
| 投资者割韭菜 | 高短期 reward | 低长期 value | 不该选 |

**贪 reward = 短视；贪 value = 远见**。RL 之所以叫"强化学习"而不是"奖励学习"，本质就是它学的是 value，不是直接学 reward。

### ⑤ 直接对应到 LLM-RL 交通控制项目

- 你现在的单步 GRPO**只有 reward，没有 value 估计**——这正是它退化成 bandit 的形式化原因。
- 修复路径中提到的 "TD bootstrap / n-step return" 本质都是**引入 value 估计**：
  - bootstrap：用 $V_\theta(s')$ 替代真实未来 → 给 GRPO 加 critic
  - n-step return：用真实未来 N 步 + bootstrap 兜底
- 任何一条都会把"看一步"变成"看长远"，对应 §1.3 这段话从理论到工程的落地。

### ⑥ 跟我心得一（"reward 函数不可学"）的边界

容易混淆的两件事：
- **reward 函数 $r(s,a)$**：不可学（设计者写死）
- **value 函数 $v(s)$ / $q(s,a)$**：必须学（agent 估的对象）

→ 一个是目标定义（外层冻结），一个是为达成目标而做的预测（内层学习）。这条边界面试容易问。

## 一句话总结（建议内化）

> **reward 定义目标（不可学），value 服务目标（必须学）。决策时贪 value 不是贪 reward——这是 RL 区别于贪心算法、监督学习的核心。**
> 几乎所有 RL 算法的进化史，本质上都是"如何更准、更快、更稳地估 value"的进化史。

# §1.3 心得三：4 要素归属辨认（Q4）

## 触发题

> 以下事物分别属于 4 要素中的哪一个？
> 1. ε-greedy 决策规则
> 2. 游戏的最终得分
> 3. 神经网络估计的 $V(s)$
> 4. AlphaGo 的蒙特卡洛树搜索使用的"假想下一步"

**答**：1=policy，2=reward，3=value function，4=model。

## 修正与补充

✓ 全对。但每条背后都有一个**容易混淆的点**值得单独记下来——这正是面试官追问的地方。

### ① ε-greedy = policy（不是 value）

- 容易错认成"value 的延伸"——因为 ε-greedy 是**基于** $Q(s,a)$ 选动作的。
- 但**判别准则**：4 要素归属看"它输出什么"。
  - 输出**动作**（或动作概率）→ policy
  - 输出**数值评估** → value
- ε-greedy 的输出是动作 → 它是 **policy**。$Q$ 才是 value。
- 一句话：**"基于 Q 的 ε-greedy"= 由 value 派生出来的 policy**，但身份仍是 policy。

### ② 游戏的最终得分 = reward（不是 value）

- 易错点：得分是"累积"出来的，看起来像 value（"长期累积奖励"）。
- **判别准则**：
  - 由**环境**给出的具体数值 → reward
  - 由 **agent 估计**的对未来期望 → value
- "最终得分"是环境在终态给出的标量 → 它是 **terminal reward** $R_T$。
- 注意：在 episodic 任务里，整局得分 $G_0 = \sum R_t$ 叫 **return（回报）**，不是 value；**value = 这个 return 的期望**：$v_\pi(s) = \mathbb{E}_\pi[G_0 \mid S_0=s]$。
- → reward / return / value 三者要分清：
  - **reward** $R_t$：环境给的单步标量
  - **return** $G_t = \sum \gamma^k R_{t+k+1}$：单条轨迹的累积，**随机变量**
  - **value** $v_\pi(s) = \mathbb{E}[G_t \mid s]$：return 的期望，**确定函数**

### ③ 神经网络估计的 $V(s)$ = value function（虽然形式是个网络）

- 易错点："神经网络模型"看起来像 model。
- **判别准则**：看 ML 意义还是 RL 意义。
  - ML 里的 model = 一个可训练函数（神经网/线性模型/...）
  - RL 里的 model = **环境的可模拟版本** $p(s'\mid s,a)$
- 神经网络在这里是 **value function 的实现载体**，不是环境模型。
- 同理：
  - **policy 网络** = policy 的实现（actor）
  - **价值网络 / Q 网络** = value 的实现（critic）
  - **世界模型 / dynamics 网络** = 环境 model 的实现
- → 三种神经网络长得几乎一样，**身份由它输出什么决定**：动作？数值？下一状态？

### ④ MCTS 的"假想下一步" = model（不是 policy 也不是 value）

- 易错点：MCTS 在做"决策"，看起来像 policy。
- 但**判别准则**：MCTS 内部的"展开" = 用一个**模拟器**预测"如果我走 a 会到 s'"——这是 model 的定义。
- AlphaGo 的特殊之处：
  - **环境 model**：围棋规则（写死的）+ 神经网络估计的转移和奖励
  - **policy**：神经网络给出的动作先验 + MCTS 访问统计
  - **value**：神经网络估计的局面胜率
  - **MCTS 本身 = "用 model 做 planning"** 的过程
- → 这道题揭示一个深刻关系：**有 model 的算法 = 算法运行时会调用 model 来 rollout**。Q-learning 不调 model，所以是 model-free；MCTS 反复调 model，所以是 model-based。

## 4 要素归属判别表（建议内化）

| 看到一个事物时问 | 它属于… |
|---|---|
| 它输出**动作**（或动作概率）吗？ | **policy** |
| 它是**环境**给的标量数值吗？ | **reward** |
| 它是**对未来累积 reward 的估计**吗？（无论是表格还是网络） | **value function** |
| 它能在不真实交互的情况下**模拟**出 (next state, next reward) 吗？ | **model** |

## 易错对照速查

| 易混事物 | 真实身份 | 关键区分 |
|---|---|---|
| ε-greedy / softmax / 直接策略网络 | policy | 输出是动作 |
| Q(s,a) / V(s) / 优势 A(s,a) / TD-target | value（或其变种） | 输出是数值评估 |
| 单局得分 / 棋局胜负 +1/-1 / 速度奖励 | reward | 环境给的标量 |
| 累积回报 $G_t$ | **return**（既不是 reward 也不是 value，是 value 的样本） | 一条轨迹的具体加和 |
| 围棋规则 / 物理引擎 / 路况预测器 / MCTS 展开 | model | 能模拟 (s,a)→(s',r) |
| policy 网络 / 价值网络 / 世界模型 | 各自所属（policy / value / model） | 看输出语义，不看是不是神经网 |
